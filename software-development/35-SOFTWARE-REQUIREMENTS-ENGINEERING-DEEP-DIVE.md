## What is Requirements Engineering?

### Definition

**Requirements Engineering**: Process of defining, documenting, and maintaining software requirements.

**Key Concepts:**
- **Requirements definition**: Define requirements
- **Documentation**: Document requirements
- **Maintenance**: Maintain requirements
- **Validation**: Validate requirements

### Real-World Analogy

**Requirements Engineering = Building Blueprint:**
- **Building**: Software system
- **Blueprint**: Requirements
- **Specifications**: Detailed specifications
- **Construction**: Development

**Software:**
- **System**: Software system
- **Requirements**: System requirements
- **Specifications**: Detailed specifications
- **Development**: Software development

## Requirements Types

### Type 1: Functional Requirements

**What:**
```
System functionality
  ↓
What system does
  ↓
Features and functions
```

**Example:**
```
User can create account
User can login
User can view profile
```

### Type 2: Non-Functional Requirements

**What:**
```
System qualities
  ↓
How system performs
  ↓
Quality attributes
```

**Examples:**
- **Performance**: Response time < 100ms
- **Security**: Encrypt sensitive data
- **Scalability**: Support 1M users
- **Availability**: 99.9% uptime

### Type 3: Business Requirements

**What:**
```
Business goals
  ↓
Business objectives
  ↓
Business value
```

**Example:**
```
Increase user engagement by 20%
Reduce support tickets by 30%
```

## Summary

Software requirements engineering is fundamental to successful software projects. Understanding requirements types, gathering, analysis, documentation, validation, and management is essential for building the right software.

**Key Takeaways:**
- **Requirements engineering**: Process of defining, documenting, and maintaining requirements
- **Requirements types**: Functional (what system does), non-functional (how system performs), business (business goals)
- **Requirements gathering**: Interviews, workshops, surveys, observation
- **Requirements analysis**: Analyze, refine, prioritize requirements
- **Requirements documentation**: Requirements specification, user stories, use cases
- **Requirements validation**: Review, prototype validation, test scenarios
- **Requirements management**: Version control, change management, traceability
- **Best practices**: Involve stakeholders, document clearly, validate requirements, manage changes

**Requirements Types:**
- **Functional**: What system does

- **Business**: Business goals
