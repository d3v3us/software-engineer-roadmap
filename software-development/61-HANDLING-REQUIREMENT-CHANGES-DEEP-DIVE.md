## What are Requirement Changes?

### Definition

**Requirement Changes**: Modifications to project requirements during development.

**Key Characteristics:**
- **Inevitable**: Changes are inevitable
- **Impact**: Can impact project
- **Management**: Requires management
- **Process**: Needs process

### Real-World Analogy

**Requirement Changes = Building Modifications:**
- **Building**: Software project
- **Changes**: Requirement changes
- **Impact**: Project impact
- **Management**: Change management

**Software Development:**
- **Requirements**: Project requirements
- **Changes**: Requirement changes
- **Impact**: Development impact
- **Process**: Change process

## PoC Phase Handling

### PoC Phase Characteristics

**Characteristics:**
- **Exploration**: Exploring solutions
- **Flexibility**: High flexibility
- **Learning**: Learning phase
- **Proof**: Proving concepts

### PoC Phase Strategy

**1. Communication:**
- **Team communication**: Communicate with team
- **Change awareness**: Make team aware of changes
- **Flexibility**: Emphasize flexibility
- **Adaptation**: Encourage adaptation

**2. Focus on Proof:**
- **Solution proof**: Focus on proving solution
- **Not perfection**: Don't focus on perfect design
- **Quick iteration**: Quick iterations
- **Learning**: Focus on learning

**3. Change Evaluation:**
- **Business reason**: Evaluate business reason
- **Technical reason**: Evaluate technical reason
- **Discussion**: Discuss changes
- **Decision**: Make informed decision

**4. Argument for Reason:**
- **Business changes**: Accept business changes
- **Technical changes**: Discuss technical changes
- **Justification**: Require justification
- **Decision**: Make decision

### PoC Phase Workflow

**Workflow:**
```
Requirement change
  ↓
Evaluate reason
  ↓
Business reason? → Accept
  ↓
Technical reason? → Discuss → Decision
  ↓
Implement change
  ↓
Learn and adapt
```

## Production Phase Handling

### Production Phase Characteristics

**Characteristics:**
- **Stability**: Need for stability
- **Quality**: High quality requirements
- **Process**: Formal process
- **Impact**: Higher impact

### Production Phase Strategy

**1. Process Setup:**
- **Change process**: Establish change process
- **Evaluation**: Require evaluation
- **Approval**: Require approval
- **Documentation**: Document changes

**2. Re-estimation:**
- **Impact assessment**: Assess impact
- **Re-estimation**: Re-estimate effort
- **Timeline**: Update timeline
- **Resources**: Assess resources

**3. Decision Making:**
- **Not urgent**: Continue work, update plan
- **Urgent**: Request resources or cut features
- **Trade-offs**: Consider trade-offs
- **Stakeholder approval**: Get approval

### Production Phase Workflow

**Workflow:**
```
Requirement change
  ↓
Evaluate impact
  ↓
Re-estimate
  ↓
Not urgent? → Continue work, update plan
  ↓
Urgent? → Request resources or cut features
  ↓
Stakeholder approval
  ↓
Implement change
```

### Change Scenarios

**Scenario 1: Not Urgent**
```
Change request
  ↓
Impact assessment
  ↓
Re-estimation
  ↓
Update future plan
  ↓
Continue current work

**Scenario 2: Urgent**
```
Change request
  ↓

  ↓

  - Request additional resources
